# Conventions

Authoritative rules live in `.claude/rules/*.md` (mirrored under `.agents/rules/*.md` — keep both in sync if editing, they appear to be duplicated for different tool contexts). Summary of durable, non-obvious points (full text is auto-loaded into agent context, so don't re-read unless verifying specifics):

- **code-style.md**: const-only (no let-mutation preference note: prefer const, never var), early returns, <50-line functions, `is/has/should` boolean naming, verb+noun function naming. TS: explicit return types on exported fns, `type` for shapes/`interface` for extendable contracts, `unknown` over `any`, discriminated unions over optional fields, `satisfies` over `as`. Errors: no empty catches, Result-pattern (`{ok:true,data}|{ok:false,error}`) for expected failures, throw only for programmer errors, always log with context. Imports grouped external→internal→relative, use `@/` aliases, no circular imports.
- **git-workflow.md**: `main` always deployable, never push directly to it. Branch naming `feat/<ticket>-<desc>` / `fix/<ticket>-<desc>`. Conventional Commits, imperative mood, atomic commits. PRs <400 lines diff where possible, squash merge.
- **testing.md**: co-located `*.test.ts`, `describe`/`it('should X when Y')`. Mock at module boundaries not internals; prefer DI over module mocking; reset mocks in beforeEach/afterEach. Factory functions for test data.
- **speckit-language.md**: Spec Kit (`/speckit-*`, `.specify/`) generated docs must be written in Japanese, except code identifiers, error codes, standard/protocol names, feature-dir slugs (ASCII kebab-case), git commit messages (Conventional Commits/English), and source code/comments (follow code-style.md).
- **development.md** (日本語, project-specific ops rules): Prefer Chrome DevTools MCP (`mcp__chrome-devtools__*`, AI-agent-only Chrome profile `chrome-ai-agent` on `[::1]:9222`) over Claude-in-Chrome for browser automation; never repurpose the user's normal Chrome profile for remote debugging. Must state evidence confidence (実コード確認/ドキュメント確認/主観/推測) for any blanket claim, and must `grep -rn` across the whole repo before asserting something doesn't exist anywhere. Large outputs (git diff, big greps, PDFs, logs) must not be dumped into the parent context — delegate to a subagent and get back only a summary/JSON. Subagent parallel launches should default to sequential in this environment (heavy MCP defs + big parent context + parallelism → "Prompt is too long" failures); if parallel is unavoidable, cap at 2-3. `git add -A`/`git add <dir>/` is unsafe with concurrent sessions — prefer explicit path staging or `git -C`.
- **proactive-subagents-and-skills.md** (日本語): Actively use Skills (read SKILL.md before applying) and Subagents (for refactoring/review/broad exploration or parallel work); state which one is used and why in one line before proceeding.
- **security.md**: validate all external input with zod at boundaries, never trust client-side validation alone, sanitize HTML output. No hardcoded secrets — env vars only, never log/echo secrets. Auth then authz on every protected route, constant-time token comparison, rate-limit auth endpoints. Parameterized queries only, least-privilege DB creds, transactions for multi-step DB ops. Security headers (CSP/HSTS/X-Frame-Options), HTTPS everywhere, validate redirect targets, explicit CORS policy.
