コード変更、AWSへのデプロイ、オンチェーン取引は行わないでください。

単なるタスク一覧ではなく、計画の合意後に実装へ進める具体性を求めています。

## 1. プロジェクトの目的

テーマ：
「AWS CDKで構築する、フルサーバーレスなSera AI Agent」

成果物は次の3つです。
1. 実際に動作するサンプルアプリ
2. 読者が環境構築・デプロイ・動作確認・削除まで再現できるREADME
3. 設計判断と主要な実装を解説する日本語の技術ブログ原稿

想定読者は、TypeScriptとReactの基礎は理解しているが、
AWS CDK、AI Agent、MCP、Sera Protocolには詳しくない開発者です。

教材としての分かりやすさ、再現性、低コスト、保守性を重視してください。

## 2. 実現したい機能

ユーザーがWebのチャット画面から自然言語で以下を操作できるようにします。

- ウォレットの作成
- ウォレットの残高確認
- Sera Protocolの板・取引情報の取得
- ステーブルコインのswap
- 送金
- 実行結果とトランザクション状態の確認

必要な入力が不足している場合は、チャットで補完します。
読み取り操作と資産を変更する操作は区別してください。

swap・送金は、対象ネットワーク、トークン、数量、送信先、
手数料やスリッページなどの必要情報を確認画面に表示し、
ユーザーの明示的な承認後に実行する設計にしてください。

LLMの文章だけで取引成功を判定せず、
ツールの実行結果とチェーン上の状態を根拠に表示してください。

## 5. アーキテクチャで決めたいこと

フルサーバーレスとは、アプリ側で常時稼働するサーバーや
コンテナの運用を必要としない構成を指します。
Privy、LLM、RPC、Seraなど外部サービスへの依存は明示してください。

以下について、採用案・理由・制約を示してください。

- フロントエンドからAPI、Agent、MCP、Seraまでの接続構成
- API Gatewayの種類とチャットの応答方式
- Lambda/API Gatewayのタイムアウトと長時間処理への対応
- 同期応答、ストリーミング、非同期処理の必要性
- sera-mcpをLambda内で起動する案と、別サービスに分離する案の比較
- MCP接続のライフサイクルとコールドスタートへの影響
- 会話履歴、ユーザーとウォレットの対応、取引状態の保存先
- Lambdaの一時領域やメモリに永続状態を依存させない方法
- 同時実行時にユーザーの認証情報や署名情報を混在させない方法
- 認証、認可、CORS、入力検証、レート制限
- ログ、監視、エラー調査に必要な情報

実装上の不確実性が大きい部分は、
先に行う小さな技術検証と、その合格条件を定義してください。
このターンでは検証コードを実装せず、検証計画を示してください。

## 6. ウォレットと取引の設計

Privyをどの役割に使うか明確にしてください。
ユーザー認証、ウォレット作成、署名、鍵管理を分けて説明してください。

ブラウザ側での署名とサーバー側での署名を比較し、
このサンプルに適した方式を提案してください。

以下を設計に含めてください。

- 認証ユーザーと操作対象ウォレットの所有関係の検証
- 秘密鍵や認証情報をLLM、ブラウザ配布物、ログへ露出させないこと
- モデルの判断だけでは送金・swapを実行できない制御
- 承認した取引内容と実際に実行する内容の一致
- 見積もりの期限切れや条件変更時の再確認
- 二重クリック、API再試行、タイムアウトによる二重実行の防止
- ブロードキャスト済みだが結果不明の取引の追跡
- 残高不足、ガス不足、署名拒否、外部API障害の扱い

開発・自動テストではテストネットまたはdry-runを第一候補とし、
実際の対応状況を確認してください。
モックによる動作と実ネットワークでの検証を明確に区別してください。

## 8. デプロイと削除

必要な事前設定が済んだ後は、リポジトリのルートから
次のような単一コマンドで操作できることを目標にします。

- pnpm deploy -- --stage dev
- pnpm destroy -- --stage dev

コマンド名・引数は計画で確定してください。

deployは、必要なコード生成、ビルド、CDKデプロイ、
フロントエンド配信設定を一貫して扱い、
完了時にアプリURLなどを表示する設計にしてください。

以下を明示してください。

- AWS認証、CDK bootstrap、Privy設定などの事前作業
- 自動化できる作業と外部サービス側で必要な作業
- 環境変数とシークレットの設定方法
- AWSリソースと外部サービスの管理範囲
- S3オブジェクト、ログ、データ、CDK bootstrapリソース等の削除・保持方針
- オンチェーンのウォレットや取引履歴は削除できないこと

「全リソース削除」と表現する場合は対象範囲を定義し、
残るものをREADMEに明記してください。
削除コマンドは、このサンプルが管理する対象環境だけに作用させてください。
